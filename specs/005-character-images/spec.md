# Spec: 登場人物リスト＋画像、カット生成での参照（005）

**Status**: 実装済み（[tasks.md](./tasks.md)）。決定は下表
**前提**: 003 絵コンテ Phase 5（カット画像の生成/添付/貼付/プロンプト・FR-115〜119）実装済み。C案（アプリ先行・個人利用）。

## 決定（Session 5）

| 論点 | 採用 |
|------|------|
| 登場人物の置き場所 | 絵コンテ作品ごと（`StoryboardContent.characters`） |
| カットの人物参照 | カットごとに手動選択（`StoryboardCut.characterIds`） |
| 実装範囲 | 一括（CRUD＋画像＋脚本プロンプト生成＋カット参照生成） |

## 1. 目的

絵コンテに**画像付きの登場人物リスト**を持たせ、カットの絵をその登場人物画像を参照して生成できるようにする。登場人物の画像は、カット画像と同じ操作系（生成／添付／貼り付け／プロンプト、その場生成 or 外部生成→取り込み）で用意する。

## 2. User Stories

- **US1（登場人物CRUD）**: 登場人物を追加し、名前・容姿説明を編集・並べ替え・削除できる。
- **US2（登場人物の画像）**: 各人物に画像を用意できる。方法は (a) 添付（ファイル）／貼り付け（クリップボード）、(b) BYOK でその場生成、(c) プロンプトをコピーして外部（ChatGPT 定額）で生成→取り込み。バージョン履歴・採用/差し戻し（カット画像と同じ）。
- **US3（脚本からプロンプト生成）**: `sourceScriptId` の脚本（登場人物表・本文）から、AI が登場人物と各人物の作画プロンプトを生成し、リストに反映する。
- **US4（カット生成での参照）**: カットに登場する人物を選び、その**採用画像を参照**してカットの絵を生成する（キャラの見た目を保つ）。参照は BYOK 生成（GPT Image edits の複数参照画像）と、外部生成用プロンプト文（参照キャラ名を明記）に反映。
- **US5（MCP 連携）**: `get_cut_context` が、そのカットが参照する登場人物（名前・容姿説明）を併せて返し、外部ホストが定額枠で見た目を揃えて描ける。

## 3. Requirements

- **FR-201（データ）**: `StoryboardContent.characters?: StoryboardCharacter[]`（`{ id, name, description, image?: CutImage }`）。`StoryboardCut.characterIds?: string[]`。いずれも任意・後方互換。
- **FR-202（画像の再利用）**: 人物画像は `CutImage`（versions/adoptedId/chat）を流用。カット画像パネルの操作系を汎用化した共通コンポーネントで扱う。
- **FR-203（保存方針）**: 人物画像も Firestore 非保存（FR-117 準拠）。`stripStoryboardImages` を拡張してカット画像＋人物画像を除去。JSON バックアップには base64 内包で往復。
- **FR-204（脚本からプロンプト生成）**: `sourceScriptId` の脚本テキストから AI が `[{ name, description, promptDraft }]` を生成（不正 JSON は非破壊、既存人物は上書き確認）。
- **FR-205（カット参照生成）**: カットの `characterIds` で選ばれた人物の採用画像を参照して生成。
  - BYOK: GPT Image（gpt-image-1）の画像編集エンドポイントに参照画像を複数渡す。
  - 外部用プロンプト: 参照する人物名と容姿説明をプロンプト文へ明記（`get_cut_context.promptDraft` も同様）。
- **FR-206（UI）**: 絵コンテ画面に「登場人物」セクション（カード=名前＋容姿＋画像パネル）。カット行に登場人物マルチ選択。操作は生成/添付/貼り付け/プロンプト。
- **FR-207（MCP）**: `get_cut_context` の返却に `characters:[{name,description}]` を追加。任意で `scenariolab_list_characters` を追加。

## 4. Success Criteria

- **SC-201**: 人物を追加→画像を添付→保存→再ロードで、人物・採用画像（バックアップ経由）が復元。
- **SC-202**: カットに人物を紐付け→BYOK 生成で、参照画像を渡した生成が 30 秒以内に成功（SC-107 準拠）。失敗時は採用画像・データ非破壊。
- **SC-203**: 脚本からの人物生成 成功率（パース成功）90% 以上、失敗時データ非破壊 100%。
- **SC-204**: 既存の脚本・小説・絵コンテ（人物なし）に本仕様起因の不具合ゼロ（後方互換）。

## 5. スコープ外（後続）

人物画像のクラウド保存（Storage）、AI 自動人物推定（カット参照の自動化）、人物の作品横断ライブラリ化、コンテスト/グループ連携。
